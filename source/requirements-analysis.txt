Building prerequisites and tiers — local resource analysis, 25 October 2026

Scope
-----
The original Infrastructure catalogue is enriched with building-property
requirements, minimum city gates, and building cost tiers from the installed
resource packages. These are static definitions, not live-save measurements.
The graph is a building-dependency reference, not a complete construction
availability simulator: culture, research, terrain, population, province,
throne-city, and other conditions can still apply.

Resource fields
---------------
TStructureUpgrade serialization was inspected in ResourceED.exe, including
the serializer at virtual address 0x1410AA180. The relevant serialized fields:

  0x07 — required structure properties
  0x08 — properties supplied by the structure
  0x30 — linked property/effect resources, including the building's ID property
  0x36 — cost definition link
  0x4D — additional property requirements, including city-level gates
  0x2D — required colony-domain requisite
  0x2E — required count of that requisite

Resource links are decoded by their 64-bit resource IDs, including links
without a text-form [#ID] marker. The root field-offset table contains a
compact-entry count and a separate wide-entry count; both count toward its
data boundary. This matters when reading the required-property fields.

Buildings are joined by their exact resource ID through their catalogue
name/icon/internal definition. Display IDs alone are not unique: some game
variants share the same display ID, including Town Hall variants.

For each required property, the graph finds building definitions supplying
that property. Buildings that require the same property themselves are not
treated as initial providers. Where later upgrades retain earlier properties,
the lowest known cost-tier providers are retained. Multiple suppliers of one
property are alternatives; separate property groups are joint requirements.
Unresolved property conditions remain in the building details.

City gates appear as labels rather than extra arrows to every economic node.
Town Hall chains can still connect Town Halls within the same culture.
Visible graph edges are restricted to the current filters. Details retain
the full mapped alternatives, including buildings hidden by those filters.

Tiers and ordering
------------------
Building tier comes from the linked cost resource name: Tier 1–4, Roman
numerals in town-hall cost names, and Guild Cost (Tier 4 + token).
It is not used as evidence for a Town Hall requirement.

Minimum city level comes from required City Tier / Town Hall properties.
Construction requirements inherit the minimum level required by their
building prerequisites; the minimum over alternatives is used for one
property group, and the maximum over joint groups is used for the building.
An ordinary city building without a higher mapped city gate is listed under
City I. This is an earliest possible city gate, subject to its other unlocks.
Province improvements have no city-level ranking. Unknown building tiers
sort after the known tiers rather than being guessed from their price.

Default list ordering is required city level, building tier, then name.
Building-tier-first, name, and largest-discount sorts are also available.

Catalogue presentation
----------------------
341 display entries remain after omitting unused/iconless definitions and
merging variants with identical name, category, origin, Infrastructure tags,
boost requirement, and required properties. The earlier visual merged some
variants without checking their different prerequisites. All 36 common
buildings now share one category. Province improvements are also one category;
the resource filters can select only improvements with a matching bonus.

Checks
------
All non-city prerequisite edges were checked for graph cycles: none found.
Browser checks cover core prerequisite chains, default city/tier ordering,
resource filters, view switching, culture selection, original icon loading,
boost totals, details, and desktop/mobile layouts.

Supporting assets
------------------
Construction costs are joined by exact resource ID from the pinned AoW4
Database structure catalogue export documented in README.md. All 341 display
entries have parsed, nonnegative costs. source/import-building-costs.cjs can
repeat the import with a local structure-catalogue.json export. The cost field
keeps gold, production, and any other resource tokens separately.

The savings calculator uses the current filtered entries in both views.
For each matching Infrastructure bonus, gold/production savings are base
cost x 0.25, additionally x 0.70 if boosts are enabled and the entry is
boostable. Selected bonus contributions add together. Cost to build uses
base cost x (1 - 0.25 x selected matching bonuses), then the boost multiplier.
Other cost resources are unaffected. Values precede whole-resource rounding;
alternative entries in a view are counted separately. Bonus selection changes
the calculator only; per-building badges still assume all bonuses unlocked.

assets/buildings-data.js contains the generated display data and prerequisite
property groups, including exact game resource IDs and relative source paths.
The original source/infrastructure-bonuses.html is retained as an archive of
the first visual. Current pages use assets/buildings.js and assets/site.css.
Names/icons/boost labels use the pinned AoW4 Database export documented in
README.md. No game binaries are distributed in this repository.
